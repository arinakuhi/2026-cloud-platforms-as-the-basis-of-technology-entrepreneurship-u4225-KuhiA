# Лабораторная работа №1

## Обзор Google Cloud и исследование основных сервисов

**Дата выполнения:** 03.11.2026

**Цель работы:** ознакомиться с Google Cloud Platform, создать сервисный аккаунт и виртуальную машину, исследовать управление доступом IAM и работу Cloud Storage.

[Полный отчёт по лабораторной №1](lab1/lab1_report.md)

### 1. Создание сервисного аккаунта

В Google Cloud Console проекта `cloud-platforms-as-the-basis` был создан сервисный аккаунт:

`akuhi-sa-lab1@cloud-platforms-as-the-basis.iam.gserviceaccount.com`

Аккаунту назначена роль **Storage Admin**, позволяющая управлять ресурсами Cloud Storage.

![Создание Service Account](lab1/images/01-service-account.png)

![Назначение роли Storage Admin](lab1/images/02-storage-admin.png)

### 2. Создание виртуальной машины

В Compute Engine была создана виртуальная машина со следующими параметрами:

| Параметр | Значение |
|---|---|
| Name | akuhi-vm-lab1 |
| Region | us-central1 |
| Zone | us-central1-a |
| Machine type | e2-micro |
| Provisioning model | Spot |
| Operating system | Debian GNU/Linux 13 |
| Boot disk | 10 GB |

К виртуальной машине подключён ранее созданный сервисный аккаунт.

![Настройки виртуальной машины](lab1/images/03-spot-e2-micro.png)

![Настройки ОС и диска](lab1/images/04-debian-disk.png)

### 3. Подключение по SSH и работа с Cloud Storage

После создания виртуальной машины выполнено подключение через SSH.

Для проверки сервисного аккаунта использована команда:

```bash
gcloud auth list
```

Активным оказался сервисный аккаунт `akuhi-sa-lab1`.

![SSH-подключение](lab1/images/05-ssh.png)

Для просмотра объектов учебного бакета выполнена команда:

```bash
gcloud storage ls gs://lab1-bucket-itmo/
```

В бакете обнаружены три файла:

- `pic1.jpg`
- `pic2.jpg`
- `pic3.jpeg`

Для загрузки файлов выполнены команды:

```bash
mkdir -p ~/lab1-files
gcloud storage cp gs://lab1-bucket-itmo/* ~/lab1-files/
ls -lah ~/lab1-files/
```

**Результат:** все три файла успешно скопированы на виртуальную машину.

```text
Completed files 3/3

pic1.jpg    228K
pic2.jpg    487K
pic3.jpeg   858K
```

### 4. Изменение прав доступа IAM

Для исследования модели доступа роль сервисного аккаунта изменена с **Storage Admin** на **Compute Viewer**.

![Изменение роли на Compute Viewer](lab1/images/06-compute-viewer.png)

После изменения роли повторно выполнена команда:

```bash
gcloud storage cp gs://lab1-bucket-itmo/pic2.jpg ~/lab1-test/pic2-new.jpg
```

Несмотря на изменение роли, файл успешно скопирован.

При анализе настроек бакета установлено, что группе `allUsers` предоставлена роль **Storage Object Viewer**, позволяющая читать объекты бакета.

![IAM-разрешения бакета](lab1/images/07-bucket-permissions.png)

![Права allUsers](lab1/images/08-allusers.png)

### 5. Завершение работы

После завершения эксперимента виртуальная машина `akuhi-vm-lab1` удалена.

### Вывод по лабораторной №1

В ходе работы были изучены основные сервисы Google Cloud: IAM, Compute Engine и Cloud Storage.

Был создан сервисный аккаунт, настроена виртуальная машина и выполнено копирование файлов из Cloud Storage.

Эксперимент показал, что эффективные права доступа определяются совокупностью IAM-разрешений. Наличие роли Storage Object Viewer для `allUsers` позволило продолжить скачивание файлов после изменения роли сервисного аккаунта на Compute Viewer.

**Цель работы:** изучить возможности Google Cloud Run для развёртывания контейнерных приложений, управления конфигурацией, мониторинга и распределения трафика между ревизиями.

[Полный отчёт по лабораторной №2](lab2/lab2_report.md)

### 1. Создание сервиса Cloud Run

В Google Cloud Console был создан сервис `akuhi-lab2`.

В качестве приложения выбран демонстрационный контейнер Google Cloud Run:

```text
us-docker.pkg.dev/cloudrun/container/hello
```

Настройки сервиса:

| Параметр | Значение |
|---|---|
| Project | cloud-platforms-as-the-basis |
| Service name | akuhi-lab2 |
| Region | us-central1 |
| Container | Cloud Run Hello |
| Container port | 8080 |
| Minimum instances | 0 |
| Maximum instances (initial) | 1 |
| Authentication | Public access |

![Создание Cloud Run](lab2/images/01-create-service.png)

![Выбор контейнерного образа](lab2/images/02-container-image.png)

Для генерации запросов страница приложения несколько раз открывалась и обновлялась в браузере.
